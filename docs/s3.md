# s3 — Object Storage CLI

A command-line tool for object storage based on the AWS S3 SDK
(aws-sdk-go-v2), for agents. It works with any S3-protocol service: AWS S3,
MinIO, Cloudflare R2, Alibaba OSS, Tencent COS, and so on.

## 1. Design principles

1. **The agent only perceives buckets, never credentials.** AK/SK, endpoint,
   region, and the S3 service are invisible to the agent and cannot be passed through
   any flag.
2. **The agent sees a single S3 service.** Whether the backend is MinIO or AWS,
   how many S3 services there are, and where the secrets come from are all
   invisible to the agent. To it there is just one object store, addressed as
   `s3://<bucket>/<key>`.
3. **Config is the boundary.** The agent can only access buckets declared in the
   config file. Adding storage is always an operator config change, so the
   agent's storage capability is explicit rather than constrained by a prompt.
4. **Secrets are never written to disk in plaintext.** See
   [§6 Secret storage](#6-secret-storage).

## 2. Three-layer model

| Layer | User | Contents |
|---|---|---|
| Discovery | agent | `s3 buckets` lists bucket names + descriptions; the agent chooses from these |
| Operation | agent | `s3 ls/put/get/cat/rm s3://<bucket>/<key>`, addressing only by bucket name |
| Config | operator | services (credentials) + buckets (mappings) + `secrets.age` (encrypted keys) |

## 3. Commands

### 3.1 Discovery

```
s3 buckets [--json]
```

Outputs the configured buckets. This is the agent's entry point; the description
field is what it chooses on.

```
BUCKET    DESC
archive   Long-term archive for historical reports, mostly read-only
incoming  User uploads, temporary files, cleaned up after 7 days
```

**Column named BUCKET**: the agent does not read the config file; all it sees is
the output of `s3 buckets`. Whether the underlying config uses an `alias` or the
real bucket name, to the agent this column is the bucket.

### 3.2 Operation

| Command | Description |
|---|---|
| `s3 ls s3://<bucket>/<prefix>` | List objects. `--recursive` for recursion; `--json` for structured output |
| `s3 put <local file> s3://<bucket>/<key>` | Upload. Large files use multipart with concurrent parts, and set Content-Type by extension |
| `s3 get s3://<bucket>/<key> <local path>` | Download. Large objects download in concurrent parts; writes to a temp file first, then atomically replaces on success, leaving no half-written file on failure |
| `s3 cat s3://<bucket>/<key>` | Write to stdout |
| `s3 rm s3://<bucket>/<key>` | Delete. Add `--recursive` to delete by prefix |
| `s3 sync <local dir> s3://<bucket>/<prefix>` (or reversed) | Directory ↔ prefix sync. See below |

`ls` is non-recursive by default (folded at `/`), matching `aws s3 ls`.

#### sync

```
s3 sync <local dir> s3://<bucket>/<prefix>    # upload
s3 sync s3://<bucket>/<prefix> <local dir>    # download
```

The direction follows the `s3://` argument: a remote destination uploads, a
remote source downloads. The prefix is treated as a folder (a missing trailing
slash is added); keys are `prefix + <relative path>`. Only regular files are
synced — symlinks and empty directories have no place in a flat key space.

**What transfers.** Objects missing on the destination, and objects whose size
differs. For equal sizes the decision goes to the `mtime` fingerprint that
`put`/`sync` stamp into object metadata: if it differs from the local file's
mtime, the stored copy is stale and transfers; if it matches, the file skips —
even though the remote `LastModified` (an upload instant on the server's clock)
is newer than the local mtime. Objects without a fingerprint fall back to
comparing timestamps (source newer → transfer, like `aws s3 sync`), which can
misjudge when the two clocks differ. `--size-only` skips the mtime check
entirely.

**Deletion is never implicit.** Without `--delete`, entries that only exist on
the destination are left alone. With `--delete` they are removed — remote
objects in batch, local files one by one — after the count is reported to
stderr, the same contract as `rm --recursive`.

`--dry-run` prints the plan without touching anything; `--json` emits the plan
(or result) as structured output on stdout. Transfers run 8 at a time; one
failed transfer does not stop the others, and the command exits non-zero when
any operation failed.

**The bare address form is refused here** (unlike every other command): a
local path like `archive/2026` would parse as a bucket address, and guessing
the direction of a command that can delete is how accidents happen. Pass the
`s3://` scheme explicitly.

**A bucket is never optional.** There is no `default_bucket` fallback — an
implicit default would point the same command at different storage under
different configs, which is a source of incidents. If the agent does not know
which buckets exist, it runs `s3 buckets` first.

### 3.3 Config (operator)

```
s3 config
```

One interactive menu manages everything; it is a browser over the config and
mirrors its shape. The top level lists the **S3 services**; selecting one opens
its screen, which shows the service's fields and the **buckets** that belong to
it:

```
S3 configuration — services
  ▶ minio   http://localhost:9000 · 2 bucket(s)
    alyun   AWS official endpoint · 1 bucket(s)
    + Add a new S3 service
    Done
```

Selecting `minio` shows its detail and its buckets:

```
minio   endpoint: http://localhost:9000   region: us-east-1   secret: configured
  ▶ archive    long-term archive for historical reports
    incoming   user uploads, temporary files
    ───────────
    + Add a bucket
    Edit this service
    Delete this service
    ← Back
```

Selecting a bucket opens that bucket's actions (edit / delete). Selecting a
service or bucket scopes the next action — adding a bucket adds it to the
current service, editing edits the entry you are standing on. Every action
returns to the screen you came from, so a single session can make many changes.

Navigate with arrows, submit with Enter. Choose `← Back` to go up a level and
`Done` to leave; Ctrl+C cancels the session outright.

- **Adding/editing an S3 service** prompts for name, endpoint, region, access
  key, addressing style, and the secret.
- `secret_access_key` is entered **without echo** — it never appears in `ps`
  output or shell history. In an edit it is left blank by default to keep the
  existing secret.
- **Deleting** a service or bucket asks for confirmation first. Deleting a
  service also removes the buckets that belong to it (cascade) — once the
  service is gone, its buckets are dead references, so they cannot stay behind.

## 4. Config file

`~/.config/agentkit/s3/config.toml`, permissions `0600`, **contains no secrets**:

```toml
[services.minio]
endpoint         = "http://localhost:9000"
region           = "us-east-1"
access_key_id    = "minioadmin"
force_path_style = true          # optional; default: true when an endpoint is configured

[[buckets]]
bucket  = "my-archive-bucket"    # real bucket name, S3 semantics
alias   = "archive"              # optional, the agent-visible short name; omit to use the bucket name
service = "minio"                # the S3 service this bucket belongs to
desc    = "long-term archive for historical reports, mostly read-only"

[[buckets]]
bucket  = "incoming"             # when no short name is needed, just write one field
service = "minio"
desc    = "user uploads, temporary files, cleaned up after 7 days"
```

### Field constraints

| Field | Constraint |
|---|---|
| `buckets[].bucket` | Real bucket name, required. May repeat across services |
| `buckets[].alias` | **Globally unique** (the agent's addressing key), optional, non-empty, must be a valid S3 bucket name, **must not contain `/`** |
| `buckets[].service` | The S3 service this bucket belongs to; must point to a defined service |
| `buckets[].desc` | Semantic description for the agent; advise describing purpose and data lifecycle |
| `services[].force_path_style` | `true` for self-hosted services (MinIO), `false` for AWS official endpoints |

**Alias and real bucket name are validated against S3 bucket-name rules**: 3–63
characters, lowercase letters / digits / dots / hyphens only, must start and end
with a letter or digit, no adjacent dots, not an IP address, and not prefixed
with `xn--`. In particular, underscores are **not** allowed.

An `alias` cannot contain `/`, because the address is split at the first `/`.
A duplicate `alias` is rejected outright at **both save and load time** (`Save`
validates before writing, refusing to produce a bad config that later commands
cannot load); there is no implicit resolution.

**A bucket with an `alias` is addressed only by that `alias`** — the real bucket
name is no longer accepted, so one bucket exposes exactly one agent-visible name
and avoids ambiguity.

## 5. Address parsing

The primary format is `s3://<bucket>/<key>`: strip `s3://`, then split at the
first `/`; the part before is the bucket, the part after is the key.

| Input | bucket | key |
|---|---|---|
| `s3://archive/2026/report.pdf` | `archive` | `2026/report.pdf` |
| `s3://archive` | `archive` | `` (empty) |
| `s3://archive/` | `archive` | `` (empty) |

Not passing an address always errors with a hint to run `s3 buckets`; there is
no default fallback.

The bare `archive/2026/report.pdf` form (without `s3://`) is also accepted — a
one-line `TrimPrefix` tolerance that absorbs the occasional LLM typo where the
scheme is omitted. Docs and examples use the `s3://` form consistently.

## 6. Secret storage

### Scheme

Machine-ID-derived key + age symmetric encryption, requiring no manual passphrase
so the agent can use it non-interactively.

```
machine_id ← macOS:   IOPlatformUUID (ioreg -rd1 -c IOPlatformExpertDevice)
             Linux:   /etc/machine-id, fallback /var/lib/dbus/machine-id
             Windows: registry MachineGuid
salt       ← "agentkit/s3/v1" + buildSalt
key        ← HMAC-SHA256(key=machine_id, msg=salt)
recipient  ← age.NewScryptRecipient(hex(key))
```

Reading `machine_id` is handled by the
[`crowdsecurity/machineid`](https://github.com/crowdsecurity/machineid) library
(a maintained fork of denisbrodbeck/machineid); this tool does not probe the
platform itself.

`buildSalt` is a compile-time injectable extra salt, **empty by default**:

```bash
go build -ldflags "-X github.com/coxlong/agentkit/internal/s3x.buildSalt=$(openssl rand -hex 16)" ./cmd/s3
```

- Without injection, behavior matches this document exactly; recompiling does not
  affect existing ciphertext.
- After injecting, **every recompile changes the key**, so an existing
  `secrets.age` cannot be decrypted and the credentials must be re-entered. That
  is the cost the adopter chooses.
- It is **not a security boundary**: a `-X`-injected string lives in plaintext in
  the binary's data segment, and `strings ./s3` extracts it without decompiling.
  Its purpose is only to make "reproducing the key from the public source" not
  work. Nothing more.

The ciphertext lives at `~/.config/agentkit/s3/secrets.age` (permissions `0600`), and the
plaintext structure is a secret-key table organized by service:

```json
{
  "minio":  { "secret_access_key": "...", "session_token": "" },
  "aliyun": { "secret_access_key": "...", "session_token": "" }
}
```

`config.toml` (non-sensitive) and `secrets.age` (ciphertext) are separated; the
former can be safely backed up and committed to git.

### Threat model

| Attacker | Defensible? |
|---|---|
| Disk image / backup / git commit / cloning the disk onto another machine | Yes, another machine cannot derive the same machine code |
| Another process on the same machine (can read `/etc/machine-id`) | No, it can recompute the key the same way |
| root | No |

This is **anti-copy, not anti-same-machine-read** — stronger than plaintext,
weaker than a system keychain (which has an OS-level per-user ACL). It is chosen
because Secret Service usually does not exist on headless Linux, and a keychain
would block non-interactive agent calls.

### Limitations

- **Containers**: multiple containers from the same image may have the same or an
  empty `/etc/machine-id` (slim images such as alpine or distroless usually do
  not have one). **This tool does not work in such containers**; it errors on
  missing machine code at startup.
- **Machine binding**: after a motherboard change, OS reinstall, or VM templating
  that alters machine-id, existing ciphertext becomes permanently undecryptable
  and credentials must be re-entered via `s3 config`.
- **When machine_id cannot be obtained it errors out directly**, with no
  fallback path; see [§7](#7-about-environment-variables).

## 7. About environment variables

**This tool reads no credential environment variables**; credentials have exactly
one source: `secrets.age`. The only environment variable consulted is
`$XDG_CONFIG_HOME`, to locate the config directory (default `~/.config/agentkit`);
it never affects the credential source.

This is deliberate. Environment variables were originally introduced as a
"fallback when machine code is unavailable", and **a fallback once present
becomes the default path** — gh CLI's plaintext downgrade is the cautionary tale
(issue #8954). Cutting it leaves only one path:

```
config.toml + secrets.age (machine-code encrypted)  →  erroring out if machine code is missing
```

Side effects:

- No need for `S3_SERVICE`: a service is a config-layer concept; operation
  commands only recognize buckets and provide no way around the bucket whitelist.
- No reading of `AWS_*`: the AWS SDK's default credential chain is **not**
  enabled; credentials always come from encrypted storage, avoiding the hard-to-
  debug situation "thought it was using the config credentials, but was
  overridden by the environment".
- **In CI or containers without machine-id the tool is unusable.** Accept that
  limitation in exchange for "a single source of credentials, no implicit
  overrides".

## 8. Error handling

When a bucket name is not configured, the error must carry the available list so
the agent can self-correct:

```
$ s3 cat s3://2026/report.pdf
error: unknown bucket "2026"; available: archive (long-term archiv…), incoming (user uploads)
run "s3 buckets" for the full list
```

A bare `NoSuchBucket` has no corrective value for an agent.

Errors are printed by main **once** (cobra's `Error:` prefix and the full usage
have been silenced), not repeated and not spammy — the error text is what the
agent corrects against, and the less noise the better.

### Bucket-name validation

Both `buckets[].bucket` and the alias must be legal S3 bucket names (see
§4). Notably, this means **underscores are rejected** and names must be 3–63
characters.

`rm --recursive` reports the number of objects it is about to delete to stderr
before deleting, so a destructive prefix delete is never silent.

## 9. Open items

- `read_only` hard constraint: currently enforced only by `desc` text, and an
  agent may not comply. If a hard guard is wanted, add `read_only = true` on the
  bucket and have the tool reject writes directly.
